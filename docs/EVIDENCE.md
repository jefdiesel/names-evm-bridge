# Evidence: what ran, where, and how to check it

<!-- SPDX-License-Identifier: MIT OR Apache-2.0 -->

One row per result. **Where** says which network. **Proofs** says what kind: *real* (proved, and for Ethereum wrapped to Groth16 and checked by RISC Zero's verifier 3.1.0 on Sepolia), *none needed* (an ordinary public LEZ transaction the sequencer executes), *executed* (the proof program was run but not proved; a mock verifier on a local Ethereum node) or *development receipts* (LEZ's development mode: the circuit runs and the block contents are real, the receipt is a stub).

Nothing here ran on a Logos network: LEZ testnet 0.4 is not live. "Our public chain" is our own LEZ v0.4.0-rc3 sequencer at `https://lez.nameswallet.app/` (JSON-RPC over POST). Nothing is audited. All funds are test funds. Work dated 2026-11-17 was built that day on branches beside `main`; where a separate AI agent reviewed it, the row says so.

## Known limits

- **Failsafe (not deployed):** `BridgeVaultFailsafe.sol` fixes `finalState` on the first update after `windDown()` without checking that LEZ minting has stopped, so a late exit can be paid while the same deposit is reclaimed (forged mints before the final also consume reclaim room). The variant is not deployed; M6's irreversible LEZ mint freeze closes it (`public-demo/prove/failsafe-20261117/README.md`).
- **v7 signers:** today's signers check neither privacy receipts nor public execution yet (they re-hash and re-extract blocks). With our stand-in keys on our one sequencer, v7 trusts us.
- **Admin timelock: closed in code for the vault, not deployed; LEZ bridge still open.** On main, `BridgeVault.sol` puts freezer changes, lifting freezes and every other weakening admin change behind `schedule` → `execute` after the immutable `adminDelay`, cancellable by the admin or the freezer; freezing stays instant (tests in `vault/test/AdminTimelock*.t.sol`; not run on any chain). The deployed vaults v2–v7 don't have it: on them these changes take effect at once. The LEZ bridge program has no timelock yet.
- **Reproducible guest builds:** reproducible guest builds with RISC Zero's Docker builder are done for the code on `main` (2026-11-28): all 10 deployable guests build with the same image id and ELF sha256 on two clean machines (two fresh GitHub-hosted runners, pre-merge CI run 46095730461; ids pinned in `VERSIONS.toml` `[[repro_guest]]`; `docs/REPRODUCIBLE-BUILDS.md`). **The deployed guests (v2–v7) were built natively before that, and none of their image ids reproduces from Docker**, including the release (`0x6bcbd714…`), trusted-tip update (`0x098f5a1a…`) and v7 seq-sig guests (`0x93c88f77…`, `0x9df4de66…`), whose guest sources and locks on main are the deployed builds' (v7: its branch tip); the bridge and token programs (`0dabbd6c…`, `ac175cb5…`) also changed lock since. Their archived ELFs stay the proving inputs for those vaults; a new deployment uses the Docker ids. Not yet checked on a machine outside GitHub.

## On public networks

Re-check: `scripts/verify-evidence.sh` reads every row below back from public endpoints (Sepolia JSON-RPC, our public chain, the deposit page), read only, with bash, curl and python3 in about a minute: each transaction's status, block, recipient and date, the vaults' and gates' fixed values, the committed Groth16 seals through RISC Zero's verifier, both light-client stores' head slot and period, and the handoff-capable store's committees. One PASS or FAIL line per check, tagged with its row. `--offline docs/evidence-answers` replays the answers saved on 2026-11-18 without a network. Expected values and the record each comes from: `docs/evidence-checks.json`.
